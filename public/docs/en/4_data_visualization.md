# Dynamic Data Visualization

**AmoxSQL** transcends the plain-text nature of traditional SQL IDEs by embedding an iterative and reactive graphical engine called **`DataVisualizer.jsx`**. This massive module (the largest file in the Frontend architecture) provides functionality usually found in full Business Intelligence tools.

---

## 1. Chart Engine Integration (Recharts)

Instead of using raw Canvas or complex raw D3, AmoxSQL wraps the **Recharts** library. Recharts enables declarative composition in React, meaning that as data or configurations (like window size or theme color) change, SVG elements transition fluidly thanks to React's algorithmic reconciliation engine.

### Supported Types
The options menu mutates React's main state by iterating through specialized components:
1.  **BarChart (Vertical and Horizontal):** Configurable to show Stacked Bars or Side by Side.
2.  **LineChart & AreaChart:** Preferred for time series. Supports stepped (`step`), monotone, or rigid linear modes.
3.  **PieChart / Donut:** Parametric sector diagrams.
4.  **ScatterChart:** Crucial for identifying outliers or the distribution of X vs Y data clusters.

## 2. Dynamic Pivot & Numeric Aggregation

Often, the query generated by DuckDB can be a `SELECT *` of tens of thousands of granular logs. The user doesn't need to go back to SQL code and type a long `GROUP BY` block and complex math functions to see it in a chart.

AmoxSQL's *Visualizer* has a JS aggregation engine:
*   If the "Group X-Axis" toggle is enabled, the interface groups the keys of the `xAxisKey` state.
*   The user can select a dynamic mathematical algorithm from the UI: `Sum`, `Average`, `Min`, or `Max`.
*   For temporal data (Time-Series Dates), there's a special interactive menu that "Pivots" the time series to collapse data by Day, Month, or Year without touching DuckDB again, facilitating the identification of monthly anomalies on the fly.

## 3. Reference Indicators (Storytelling)

For true "Storytelling" modeling, analysts need to visually annotate where critical events occurred in the life of business data.

*   **Reference Lines:** Mathematically integrated. An operator can draw a red line at `Y = 10,000` labeled "Q4 Sales Target" to demonstrate at a glance whether a business expectation was exceeded.
*   **Reference Areas:** Allows illuminating the background (background fill with configurable opacity) of a time space in the chart, like coloring the entire month of "December" in a soft color to indicate "End of Year Promotions."

## 4. Numeric & Aesthetic Persistence

### Smart Number Formatting
The user can change the representation on their axes (Y and Tooltips):
*   **Raw:** JavaScript literal `(1000000)`.
*   **Compact:** Dynamic scale to the American standard `(1M, 1.5K)`.
*   **Currency:** Prepends the dollar sign or parameterized currency.
*   **Percentage:** Intercepts decimal Tooltips multiplying by one hundred.

### `*.amoxvis` Format
Building a perfect chart—with labeled axes, custom colors from its palette picker, 45-degree rotations for long headers, adjusted margins, and legends—takes time.

To prevent losing this work, the giant JSON customization state in the Visualizer Component's memory is dumped via the explorer API to an `.amoxvis` file within the project folder. These files travel directly with code versioning in Git alongside `*.sql` files.

### Ultra-Resolution PNG Export
Using the `html2canvas` technique injected alongside pixel density multipliers (parametric Device Pixel Ratio), the explorer doesn't do a mere "Screenshot" of the dirty screen. Instead, it imperatively clones the SVG node rendered in memory, digitally enlarges it (up to a 4x scale modifier for retina), deactivates IDE borders, and prints the immaculate chart as PNG ready to integrate into executive presentations or institutional slides.
